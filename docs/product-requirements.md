# VoxInk 产品需求

## 目标与定位

VoxInk（声墨）是 Windows 跨应用智能语音输入前端。它把用户通过全局快捷键开始的一次语音输入，转成可见的临时文本和可安全交付给目标应用的最终文本。

## 当前状态与非目标

- 阶段 0 当前只有设计与脚手架；录音、真实 ASR、Windows 注入、托盘、GUI 和 SQLite 均尚未实现。这是当前状态，不是最终 MVP 的永久排除项；
- 不模拟当前 IME 的 composition，也不将退格重写 partial 作为默认方案；
- 不把 `mimo-v2.5` 表述为已与 `mimo-v2.5-asr` 专用 ASR 等价，也不把完整音频后的结果流伪装成实时 ingress；
- 不默认保存原始音频，不收集或提交供应商密钥。

## 用户流程

1. 用户把焦点放在目标应用并触发全局快捷键。
2. VoxInk 创建新的 `SessionID`、开始收音，并在悬浮层显示音量和 `Partial`；单次会话最长 60 秒。
3. 非流式路径在录音继续时按停顿渐进切段并顺序识别；用户结束收音或达到 60 秒上限后冲刷尾段，但停止录音不等于识别完成。
4. 音频段队列排空后，VoxInk 产生完整 `Final` 或明确的失败信息。
5. VoxInk 依据当前输出策略交付最终文本；若焦点已变化或注入不安全，降级为 `Copy Only` 并告知用户。
6. 用户可在未来的历史面板浏览、复制或重新输出文本。

## 供应商与音频处理

- 未来以 `AsrVendor` 供应商中心作为配置、能力声明和引擎选择核心；具体模型属于供应商配置。当前 `internal/domain` 的 Provider/Session 类型仍是稳定骨架，本轮不改变代码，`AsrVendor` 是后续实现目标和迁移边界。
- 语音转文字只配置一个主供应商和一个备用供应商，且两者不得相同；默认不并行双发。每段先调用主供应商，失败后把同一段内存 PCM 交给备用供应商；主备均失败时必须显示明确错误，不能静默丢段。
- MiMo 供应商内部可选 `mimo-v2.5-asr` 或 `mimo-v2.5`。两者可以共享 endpoint 和凭据，但请求体、能力语义及验收标准不同。
- Streaming、File/Batch、Audio Understanding 保留能力区别，由供应商能力与具体模型配置决定执行路径，不强行统一协议请求。
- 单次会话最长 60 秒。原始 PCM 仅保存在该会话内存中，待识别、拼接和错误处理完成后释放，默认不落盘。
- 非流式/文件识别使用停顿渐进切段：最短有效语音 500ms、连续静音 600ms、无停顿最大段长 15 秒；检测到停顿时在静音区间中点切段，录音继续。用户停止或达到 60 秒硬上限时冲刷尾段；500ms 只限制普通自动封段，非空短尾仍提交。
- 音频段进入单一 FIFO，按录制顺序逐段识别和拼接，不并行乱序。中文结果直接拼接；ASCII 字母或数字边界按需要补空格。只有队列排空后才产生完整 `Final`。
- 所有 Provider/UI 事件继续受当前 `SessionID` 门控；迟到事件不得覆盖新会话。

## MVP 功能

- 全局快捷键、会话状态与悬浮层 partial/final 回显；
- 一个可用的实时 ASR 路径（阶段 1 目标为火山 V3）；
- `SendInput`、`Clipboard Paste`、`Copy Only` 的可配置默认输出及安全降级；
- 最终文本的历史记录与设置入口。

## 阶段 1 验证范围

阶段 1 至少覆盖全局快捷键、麦克风采集、供应商配置与不同主备供应商、上述停顿切段、火山 V3 实时路径、MiMo 文件路径、`SessionID` 门控、partial/final 悬浮层，以及最小错误和脱敏诊断。阶段 1 仍不包含实际 Windows 文本输出、历史/SQLite、完整托盘设置、TSF 或正式发布；这些排除不缩减最终 MVP 目标。

## 历史面板与设置

历史面板计划使用 SQLite 保存最终文本、时间、供应商、输出结果及必要的会话元数据；默认不保存原始音频。设置计划包括快捷键、主/备用供应商、供应商内模型、输出策略、是否允许稳定增量输入以及历史保留策略。具体 schema、保留期和迁移策略尚未决定。

## 隐私与安全

- Provider 凭据未来仅通过 Windows DPAPI 或 Credential Manager 保存；本仓库当前不保存任何密钥。
- 阶段 1 已明确：收音期间音频发送至火山实时识别；主线路失败时，同一会话音频可能串行发送至 MiMo；原始音频默认仅驻留会话内存且不保存，active overlay 显示固定中文告知。最小诊断仅保留有界结构化元数据，不含正文、原始错误、凭据或音频，详见[隐私与诊断](privacy-diagnostics.md)。
- 供应商账户侧数据留存、训练使用、处理地域和删除政策仍须按真实账户及当期条款确认，不由本地“不落盘”保证外推。
- 输出时必须检查焦点与可注入性；不能确认安全时只复制，不尝试破坏性重写。

## MVP 验收标准

1. 按快捷键可建立、结束和明确展示一次会话；旧会话结果不会显示到新会话。
2. 实时 Provider 可将 partial/final 区分显示；最终结果可按选定策略输出。
3. 输出不安全、焦点变化或注入失败时，最终文本仍可通过 `Copy Only` 保留给用户。
4. 历史默认只存文本和元数据，不存原始音频；密钥不进入日志、历史或仓库。
5. 批量 ASR、`mimo-v2.5` 的受控 prompt 转写候选和 Audio Understanding 的选择不会影响实时收音路径的正确性。

MiMo 的模型分类、完整音频边界和验收要求见[研究证据](research/providers/mimo.md)。
